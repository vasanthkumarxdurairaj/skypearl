## 2. Matching criteria

| Criteria               | Matching rule                                                             |
| ---------------------- | ------------------------------------------------------------------------- |
| Budget                 | Prioritize properties within the buyer's budget                           |
| Location               | Match preferred Chennai localities and acceptable nearby areas            |
| Property type          | Apartment, villa, independent house, land or commercial                   |
| Size and configuration | Match bedrooms, square footage and other requirements                     |
| Purpose                | Sale, rental, investment or commercial use                                |
| Amenities              | Compare parking, furnishing, lift, security and other preferences         |
| Availability           | Exclude sold, rented or inactive listings                                 |
| Seller requirements    | Consider expected price and negotiation flexibility                       |
| Urgency                | Prioritize buyers ready to transact and listings that meet their timeline |

Hard requirements—such as a strict maximum budget or required property type—should be respected. Optional preferences can influence the match score.

## 4. Matching score

Use a configurable score from 0–100 to rank compatible listings.

Budget fit

30%

Location fit

25%

Property type and size

20%

Amenities and preferences

15%

Timing and readiness

10%

Suggested weights; the final score should reflect actual buyer preferences. Hard requirements override a high score.

Suggested score labels:

- 85–100: Excellent match
- 70–84: Good match
- 50–69: Possible match
- Below 50: Low priority

A score is a ranking aid, not a guarantee that the buyer will purchase.

## 6. Important business rule

Bab, the system should recommend and connect—not automatically promise or close a deal. Agents must confirm property availability, verify the details, and obtain appropriate permission before contacting a buyer or seller.

Also, the matching engine needs a shared database of buyer requirements and active property listings. Without that, it cannot find matches across different employees' accounts.

My recommendation: make SmartMatch a dedicated module in the sidebar, with three views: Buyer → Properties, Property → Buyers, and All Matches. That gives SkyPearl a complete matching workflow instead of just a search filter.
