This section connects to your own Supabase project. It does not make the app shared until you create the database table, enable Row Level Security, and sign in. Use only your project's anon/public key here — never a service-role key.
Not connected. Follow the setup SQL in the included README before signing in.
Database setup SQL and safety notes
create table if not exists public.skypearl_workspace (
  id text primary key default 'main' check (id = 'main'),
  payload jsonb not null default '{"records":[]}'::jsonb,
  updated_at timestamptz not null default now(),
  updated_by uuid references auth.users(id)
);
alter table public.skypearl_workspace enable row level security;
create policy "authenticated team can read workspace" on public.skypearl_workspace
for select to authenticated using (true);
create policy "authenticated team can insert workspace" on public.skypearl_workspace
for insert to authenticated with check (true);
create policy "authenticated team can update workspace" on public.skypearl_workspace
for update to authenticated using (true) with check (true);
-- Run once in Supabase SQL Editor. Only invited/approved users should have accounts.
-- Add your teammate in Supabase Authentication → Users / invite user.
Team safety: this simple shared-workspace policy allows every authenticated account in this Supabase project to access the shared CRM. Keep the project dedicated to your team and only create/invite trusted users. For production, add role-based permissions, audit history, conflict resolution and scheduled server-side backups.
